> *This was generated by AI during triage.*

Found during `/roster` QA (2026-09-08) while re-testing `/manager` after
switching the local dev server to load the real `.env` (which enabled
`GOOGLE_MAPS_API_KEY`, surfacing this for the first time locally). Same code
as the deployed GOV PaaS `api-server` — a pre-existing race, not caused by
local dev.

## What happened

```
ReferenceError: google is not defined
    at buildCarIcon (manager:2326:21)
    at render (manager:2477:12)
    at fetchAll (manager:2019:7)
```

## Root cause

`artifacts/api-server/src/routes/manager.ts`:
- `fetchAll()` runs immediately on page load (`fetchAll(); setInterval(fetchAll, 10000);`).
- The Google Maps script tag loads `async defer` and only calls `initMap()`
  (which sets up `google.maps`) whenever Google's script finishes — not
  guaranteed to happen before that first `fetchAll()`.
- `fetchAll()` → `render()` → `buildCarIcon()` references `google.maps.Size`/
  `google.maps.Point` with no guard, so a cold load where the data fetch wins
  the race throws.

Self-healing in practice (the 10s `setInterval` retries and usually succeeds
once Maps has loaded), but a real, previously-unnoticed bug, not local-dev
noise — the "loaded directly without loading=async" console warning right
next to it is unrelated Google-console nagging, not the cause.

## Fix applied

Added a `mapsReady` flag (`manager.ts`, near the other map globals), set
`true` inside `window.initMap` once the callback actually runs (which also
now calls `render()` immediately so markers don't wait for the next poll).
`render()` gates all `google.maps.*` marker/route drawing behind that flag —
everything else in `render()` (stats, roster table, alert banner, side
panels) still updates normally regardless of Maps' load state.

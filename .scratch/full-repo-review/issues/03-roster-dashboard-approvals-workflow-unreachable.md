**Significant finding while verifying, worth a human decision**:
`POST /api/leave-requests` (the only live create path, used by
`SwapLeaveApply.tsx`) has committed every new leave request straight to
`status: "APPROVED"` / `coverStatus: "ACCEPTED"` / `icStatus: "APPROVED"`
since commit `05a48a8` (2026-06-02, predates this review) —
`PENDING_COVER`/`PENDING_IC` are never produced by the current live app at
all. So the actual, present-day impact of "requests get stuck forever" is
zero for *new* requests; the fix here mainly (a) matters for old records
already sitting in those states from before that change (or from any
future code path that reintroduces a pending flow), and (b) closes the
code-reachability gap the ticket describes, which is real regardless.
Worth asking a human whether the June auto-approve change was intentional
(if so, PENDING_COVER/PENDING_IC and the whole cover/IC review concept may
be semi-vestigial and worth a bigger product conversation) — did not
change that behavior here, out of scope for this ticket.

Also found, not fixed (separate, narrower, pre-existing bug, not in this

## Agent Brief

**Category:** bug (data-safety — missing API, dangerous default)
**Summary:** There is no way to delete a single inspection — `DELETE /api/inspections` always deletes every inspection (default `mode=all`), and at least one existing script relies on the wrong assumption that it doesn't.

**Current behavior:**
`DELETE /api/inspections` in `artifacts/api-server/src/routes/inspections.ts`
(~lines 478-484) defaults to `mode=all`, deleting every inspection row and its
MinIO photo objects. `scripts/src/test-photo-remarks.ts:232` calls this
expecting to remove only the inspection it just created, logging the
misleading "Test inspection deleted" — running this script against any
environment with other real or test data destroys all of it, permanently
(photos included).

**Desired behavior:**
A `DELETE /api/inspections/:id` route exists that removes exactly one
inspection and its photos. The bulk `mode=all` route stays available for
intentional full clears but is not the only option.

**Key interfaces:**
- `artifacts/api-server/src/routes/inspections.ts` — add the scoped route alongside the existing bulk one
- `scripts/src/test-photo-remarks.ts:232` — switch its cleanup step to the new scoped route

**Acceptance criteria:**
- [ ] `DELETE /api/inspections/:id` deletes exactly one inspection (row + MinIO photos) and leaves all others untouched
- [ ] `scripts/src/test-photo-remarks.ts` uses the scoped route for its cleanup step
- [ ] The bulk route continues to work for its existing legitimate use (full clear from the Manager Dashboard) but requires explicit `mode=all` or equivalent confirmation, not just being the only option available

**Out of scope:**
- Auth on either route (tracked in `01-api-server-missing-auth-middleware.md`)

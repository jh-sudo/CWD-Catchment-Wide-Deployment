## Agent Brief

**Category:** bug
**Summary:** Session cookies silently fail to set in production behind a TLS-terminating proxy

**Current behavior:**
The session cookie config sets `secure: true` when `NODE_ENV === "production"`. The
Express app never calls `app.set("trust proxy", ...)`. Deployed behind a
TLS-terminating edge proxy (e.g. Northflank), the Node process only ever sees
plain HTTP internally, so Express's `req.secure`/`req.protocol` always report
insecure — `express-session` then silently refuses to set the cookie.

**Desired behavior:**
The app trusts its edge proxy's forwarded-protocol header so `req.secure`
correctly reflects the original client connection, and the session cookie is
set on every successful login in production.

**Key interfaces:**
- The Express app instance — needs `trust proxy` configured before the
  session middleware is registered.

**Acceptance criteria:**
- [ ] `app.set("trust proxy", ...)` (or equivalent) is configured before
      `express-session` middleware
- [ ] A login request behind a TLS-terminating reverse proxy results in a
      `Set-Cookie` header on the response in production mode
- [ ] Subsequent authenticated requests using that cookie succeed (no 401)

**Out of scope:**
- Changing the cookie's `maxAge` or `httpOnly` settings

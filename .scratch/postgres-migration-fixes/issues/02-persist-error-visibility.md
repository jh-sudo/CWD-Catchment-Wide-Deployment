Found during code review of the JSON→Postgres migration diff. All deployment-state
DB writes go through a fire-and-forget `persist()` helper that only
`console.error()`s on failure while the in-memory Map and HTTP response
already report success.

**Scope note (added during triage/fix):** the fire-and-forget pattern here is a
deliberate, documented architectural choice — in-memory Maps stay the
synchronous source of truth within a running process, Postgres is
background durability, specifically so the surrounding business logic
didn't need rewriting for this migration. Converting every write path to
synchronously await and surface failures to the HTTP caller would be a
real architecture change across ~20 call sites in this file (and
the same pattern likely exists in other route files), untestable here
against a live Postgres. The maintainer chose the safer, smaller
mitigation below over the full rewrite.

## Agent Brief

**Category:** bug
**Summary:** Background persistence failures are logged with `console.error` and never retried, risking silent data loss on transient DB errors

**Current behavior:**
A failed background Postgres write is logged once via `console.error` and
otherwise dropped. If the process restarts before a retry, the mutation is
gone with no record.

**Desired behavior:**
A failing background write retries a few times with backoff before giving
up, and any failure (transient or final) is logged through the app's
structured logger at a severity that's actually alertable in production,
not `console.error`.

**Key interfaces:**
- The `persist(fn, label)` helper — should retry `fn()` a bounded number of
  times with backoff, and log through the structured logger on both
  transient and terminal failure.

**Acceptance criteria:**
- [ ] A transient failure in the wrapped write is retried at least twice
      before being given up on
- [ ] Terminal failure (all retries exhausted) is logged via the structured
      logger, not `console.error`
- [ ] No caller-facing behavior changes (still fire-and-forget — this is a
      visibility/resilience improvement, not an architecture change)

**Out of scope:**
- Converting write paths to synchronously await and surface failures to the
  HTTP caller (full architecture change, deferred — see scope note above)
- Applying the same treatment to other route files' persistence helpers

## Agent Brief

**Category:** bug
**Summary:** A request can arrive before boot-time state hydration finishes and see empty data

**Current behavior:**
Deployment state hydration from Postgres kicks off at module load but is not
awaited before the HTTP server starts listening. A request landing in that
gap sees an empty roster/assignments/locations even though Postgres holds
full data.

**Desired behavior:**
The server does not begin accepting connections until boot-time state
hydration has completed (or definitively failed and logged).

**Key interfaces:**
- The module's hydration entry point should expose a promise the server's
  startup sequence can await before binding the listening port.

**Acceptance criteria:**
- [ ] The HTTP server does not call `listen()` until hydration has settled
- [ ] A hydration failure is logged but does not prevent the server from
      starting (matches prior risk profile — failing hydration is not worse
      than before, just no longer racy for the common case)
- [ ] No route handler can observe empty state due to a startup race under
      normal (successful hydration) conditions

**Out of scope:**
- Adding readiness gates for other modules' boot-time loads (e.g. auth.ts's
  seedAdmin) unless they show the same symptom

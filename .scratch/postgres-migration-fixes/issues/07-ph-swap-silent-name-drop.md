## Agent Brief

**Category:** bug
**Summary:** Unrecognised officer names in a PH swap import silently vanish

**Current behavior:**
The import endpoint already returns a `skipped` count in its response, but
the frontend that calls it never reads the response body at all — so a
mismatched name causes real data loss (that swap never gets recorded) with
literally no signal reaching the user.

**Desired behavior:**
The importing user is shown, prominently, which specific names couldn't be
matched, so they can fix the source data and re-import rather than
discovering the gap later.

**Key interfaces:**
- The import response shape — should include not just a count but which
  entries were skipped and why (which name(s) didn't match).
- The frontend's import handler — must read the response and surface the
  warning to the user, not just fire-and-forget the request.

**Acceptance criteria:**
- [ ] The import response includes the specific unmatched name(s) per
      skipped entry, not just a count
- [ ] The frontend reads this response and displays a visible warning
      listing the unmatched names when any entries are skipped
- [ ] A fully successful import (no skips) still shows a normal success
      message

**Out of scope:**
- Fuzzy-matching names to reduce false-negative skips (separate
  enhancement)

## What happened

`ApplicationsManage.tsx`'s `handleClearHistory("all")` → `DELETE
/api/roster-plan/history/clear?mode=all` unconditionally truncates `rosterLeavesTable`,
`rosterSwapsTable`, and `rosterOverridesTable` for the **entire system**. The only confirmation is
a client-side text box requiring the user to type "DELETE" — trivially satisfied, no server-side
second factor, no automatic backup.

The button (`canClearHistory`) is shown to admin, manager, **and IC** — but the backend only
allows admin/manager, so IC users hit a dead-end 403. A permission mismatch in its own right,
separate from the main issue.

Replit's fork-since diff removes this entire "Clear log"/"Wipe everything" UI and replaces it
with an admin-only "Restore from Backup" flow instead — i.e. Replit's own team concluded this
self-service nuke was too dangerous to keep.

## Fix

Recommend porting the removal (or, at minimum: restrict `canClearHistory` to admin-only to fix
the IC dead-end, add a real server-side backup-before-delete, and require a second confirmation
step beyond a client-side typed string). This is a genuine safety issue given what the button
does today — worth prioritizing over most of the other tickets in this batch.

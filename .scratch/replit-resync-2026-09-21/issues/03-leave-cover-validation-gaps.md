## What happened

This repo has two separate leave-application surfaces, and both are missing the same class of
validation that Replit's fork-since code added:

**`POST /roster-plan/leave`** (`artifacts/api-server/src/routes/rosterPlan.ts`, ~line 853-942)
and **`POST /leave-requests`** (`artifacts/api-server/src/routes/leaveRequests.ts`) both currently
allow:
- A manager to apply DAY/PD leave for an officer with **no cover officer at all** — silent
  unfilled shift, no warning.
- A cover officer to be assigned who is themselves working, already on leave, or already
  covering someone else that date (no double-booking check).
- An officer to be named as their own cover (self-cover).

**`SwapLeaveApply.tsx`**'s `canSubmitLeave` (~line 377) has the matching frontend hole — it only
checks that cover data finished loading, never that a cover was actually picked:
```js
return dates.every(d => { const info = dateCovers[d]; return info && !info.loading; });
```
Its cover-officer candidate dropdown also doesn't exclude officers who are already committed as
someone else's cover that day, so the same officer can be picked twice.

## Fix

Port Replit's validation, applied to both `rosterPlan.ts`'s and `leaveRequests.ts`'s leave-apply
routes:
- Reject (400) if `coverOfficer.id === officer.id` (self-cover).
- Require a cover officer whenever the absent officer's scheduled duty is DAY or PD.
- Validate the chosen cover is actually available (OFF/REST on weekends, ND/OFF on weekdays) —
  400 otherwise.
- Reject (409) a cover officer who is already on leave or already covering someone else that
  date.

On `SwapLeaveApply.tsx`: fix the gate to
`return info && !info.loading && (!info.needsCover || !!info.selectedCoverId);`, and filter the
cover-candidate dropdown to exclude officers with `duty.coveringForOfficerName` already set.

**Not included here** — flagged as a separate new-capability decision in `map.md` item 10: the
"chain of cover" auto-reassignment Replit also added (when an officer who is themselves covering
someone gets granted leave, automatically requiring/wiring a replacement rather than leaving that
post uncovered again). That's an automation on top of validation, not itself a bug fix.

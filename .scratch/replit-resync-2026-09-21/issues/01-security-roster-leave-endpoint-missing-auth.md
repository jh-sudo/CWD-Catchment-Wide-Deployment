## What happened

`GET /api/roster-plan/leave` (`artifacts/api-server/src/routes/rosterPlan.ts`, ~line 844) has no
auth middleware at all — confirmed no app-level session guard wraps `rosterPlanRouter` either
(`routes/index.ts` just does `router.use(rosterPlanRouter)`). Any request, authenticated or not,
can read every officer's leave type, date, and covering-officer for any date.

The sibling `POST`/`DELETE` routes on the same resource already require manager/roster-editor —
only the `GET` was left open, which suggests an oversight rather than an intentional public read.

## Fix

Add `requireManager` (or equivalent) to the `GET` route, matching the sibling routes. Replit's
current version additionally restricts a `crew`-role session to only see their own `officerId`'s
leave rows (rather than blocking crew entirely) — worth doing the same here if crew currently has
any legitimate reason to hit this endpoint (e.g. to see their own leave history); otherwise a
flat `requireManager` is the minimal fix.

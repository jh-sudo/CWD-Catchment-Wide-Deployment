## What happened

1. **Strength count inflated.** `strengthByDate` in `OverrideEditor` counts *scheduled* duty
   only (not actual/override duty) and doesn't exclude `TBC` placeholder units. TBC-exclusion is
   already an established convention elsewhere in this repo's own backend (`rosterPlan.ts`,
   `phRoster.ts`) — just missing here.
2. **Frozen name column ambiguous.** Shows only `o.name.split(/\s+/)[0]` (first name) — ambiguous
   when two officers share a first name.
3. **Bulk save not atomic.** `save()` posts one request per date in a loop; if any date fails
   mid-loop, earlier dates are already committed server-side but `pendingRef` is never cleared,
   leaving the UI in a confusing partial state with only a generic "Save failed."
4. **Unit-code regex too narrow.** `UNIT_CODE_RE` is `[A-Z]{2}\d{1,2}` (max 2 digits) — any
   3-digit unit code gets misclassified as an officer name rather than a cross-post unit in the
   OT/CVG column.
5. **Missing leave codes on import.** `EXCEL_LEAVE` is missing several codes (`MA`, `OIL`, `PCL`,
   `PMC`, `PMMA`, `PMOVL`) — these are currently silently dropped by the Excel importer instead
   of being recorded as leave.

## Fix

1. Split actual-vs-target duty counting and exclude TBC units in `strengthByDate`.
2. Show the officer's full name in the frozen column (widen it as needed).
3. Batch all dates into one atomic multi-date save request instead of a per-date loop; surface a
   clear failure state that doesn't leave `pendingRef` stuck.
4. Widen `UNIT_CODE_RE` to allow up to 3 digits.
5. Add the missing leave codes to `EXCEL_LEAVE`.

Not included — flagged as a larger new-capability decision in `map.md` item 9: multi-date bulk
Excel import (horizontal/vertical parsers), a revert-import button, per-cell comments, and
full-year export. This ticket is bug fixes to the existing single-date importer only.

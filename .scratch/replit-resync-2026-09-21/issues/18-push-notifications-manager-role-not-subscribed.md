## What happened

`Layout.tsx` (shared shell for /crew, /manager, /roster) only auto-subscribes push for the crew
role: `usePushSubscription(user?.role === "crew" ? user.officerId : undefined)`. Managers,
admins, and ICs using the roster-dashboard shell never get auto-subscribed for push at all (only
the separate `/manager` map page has its own manual opt-in).

The hook itself (`usePushSubscription.ts`) and backend (`push.ts`) also need widening — the
current signature hardcodes `type: "crew"` and only accepts an `officerId`, rather than deriving
`type` from the actual role and accepting a full user/account id.

## Fix

Change `Layout.tsx` to call `usePushSubscription(user)` for all roles, and widen
`usePushSubscription.ts`'s signature (and `push.ts`'s corresponding backend handling) to accept
the full user object and set `type` from the actual role rather than hardcoding "crew".

Not included — flagged as a separate new-capability decision, not a bug fix: per-sector lightning
push filtering (`lightningSectors`, `sendLightningToCrew`) and a generic `sendToAccount` helper,
both tied to the lightning sector-selection feature in `map.md` item 11.

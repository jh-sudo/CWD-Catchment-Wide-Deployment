## What happened

`lib/db/src/schema/rosterLeaves.ts` already has `appliedBy`/`appliedAt` columns (correction: the
original triage report also mentioned a separate `appliedByName` column, but the schema only has
these two — `appliedBy` itself holds the display-name string, there's no separate id/name pair),
with a schema comment describing exactly this purpose ("who/when this leave entry was first
applied... preserved on every subsequent write"). But `POST /roster-plan/leave`
(`artifacts/api-server/src/routes/rosterPlan.ts`) never wrote to them — it only wrote the
applier's name into the activity-log entry, not onto the leave row itself.

## Fix

Set `appliedBy` and `appliedAt` on the `.values(...)` insert, deliberately left out of the
`.onConflictDoUpdate({ set: ... })` clause so a later edit/re-import never overwrites who
originally applied the leave, matching the schema comment's stated intent.

## What happened

Replit's `phRoster.ts` added two self-checks that this repo's `autoAllocate` doesn't have:

- `assertNoHRCrossHolidayDoubleDuty(ref, year)` — throws if the same officer is scheduled for
  both Hari Raya Puasa and Hari Raya Haji in the same year.
- `assertBalancedPHCounts(ref, year, eligibleNames)` — throws if any eligible officer's total
  PH-duty count for the year falls outside the fleet-wide min/max band, or if an ineligible
  officer appears at all.

## Fix

Port both checks into this repo's `autoAllocate` (`artifacts/api-server/src/routes/phRoster.ts`),
run at generation time, throwing (not silently persisting) on violation.

## Comments

- 2026-09-21: Fixed. Implemented as two standalone functions run in the `POST /ph-roster-ref/
  auto-allocate` route right after `autoAllocate()` returns (rather than inside `autoAllocate`
  itself, since its internal per-officer count tracking is local state not exposed to callers) —
  recomputed from the returned generated roster instead. Both wrapped in a try/catch so a thrown
  violation becomes a 500 response instead of an unhandled rejection. The balance check excludes
  OIL-copy (in-lieu) dates from counting, since those duplicate the original PH's names and would
  otherwise double-count. Threshold for "balanced" is max-min ≤ 1, matching what the existing
  `autoAllocate` swap loop already visibly tries to converge on.

## What happened

In `artifacts/roster-dashboard/src/components/RosterListView.tsx`:

1. **Named cover can be wrongly consumed by the positional cross-post queue** (~line 260-280).
   The current matching (`_crossPosters`/`ai` sequential counter) assigns the next queued
   cross-poster to every absent officer in crew-position order, without first checking whether
   that officer already has an explicit named cover (`coveringMap[o.id]`). Consequence: an
   officer with an explicit named cover can still consume a slot in the cross-post queue meant
   for someone else, so (a) the displayed covering name (correctly taken from `coveringMap`) gets
   paired with the *wrong* source-unit bracket, and (b) a later, genuinely-vacant slot has
   nothing left to pull from the queue. Replit's fix resolves all officers with an explicit
   `coveringMap` name against the remaining queue **by name** first (removing matches from the
   pool), then falls back to positional assignment only for the truly-unnamed remainder. Cited
   real repro from Replit's own comment: "Syafeeq CP3 → CP2" previously went unfilled.
2. **`coveringOfficerNameSet` missing.** Replit tracks the union of leave-based `coverForMap` and
   schedule-based `coveredByOfficerName` covering, and factors it into "already absent"/surplus
   checks. Without it, an officer covering another unit via a schedule override (not a leave)
   risks being miscounted as idle/available for auto-redirect.
3. **Two edge-case display states missing**: `isCoveredWithShift` (a covered officer whose own
   duty was also shifted to a different shift type — should be treated as absent/gone-elsewhere,
   not still "present") and `isOffSwap` (an officer who moved a scheduled working day to OFF
   today — should show struck-through with an "[Off swap]" tag). Without these, the grid can
   mis-render these specific cases as plain-present or plain-OFF with no indication of what
   actually happened.

## Fix

Port the by-name-first resolution order for cross-post matching, add the
`coveringOfficerNameSet` check to availability/surplus logic, and add the `isCoveredWithShift`/
`isOffSwap` display states.

Note: the strength-bar coloring in this same file (static 2-tier vs. Replit's dynamic 3-tier) is
tracked separately as a scope decision — see `map.md` item 6 — not part of this ticket.

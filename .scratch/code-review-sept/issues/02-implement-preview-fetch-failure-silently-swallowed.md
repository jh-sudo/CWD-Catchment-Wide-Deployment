## Agent Brief

**Category:** bug (silent failure re-opens the hole the fix closed)
**Summary:** If the new `implement-preview` fetch fails (expired session,
500, brief network hiccup) between opening the Implement dialog and
confirming, `RosterBuilder.tsx` silently drops to no warning at all —
IMPLEMENT still proceeds, mass-deactivating officers with none of the
concrete-names warning the fix was built to surface.

**Current behavior:**
`artifacts/roster-dashboard/src/pages/RosterBuilder.tsx:1187-1191`:
```ts
fetch(`/api/roster-patterns/${pattern.id}/implement-preview`)
  .then(r => r.ok ? r.json() : Promise.reject(new Error("Could not load preview")))
  .then(data => { if (!cancelled) setImplPreview(data); })
  .catch(() => { if (!cancelled) setImplPreview(null); })
  .finally(() => { if (!cancelled) setImplPreviewLoading(false); });
```
Any non-2xx or network error resolves to `setImplPreview(null)`. The warning
panel only renders when `implPreview` is truthy, and the IMPLEMENT button is
disabled only on `implementing || !implDate || ...` — not on preview failure.
So a transient failure reproduces exactly the pre-fix state: the operator
sees no per-officer warning and can still type IMPLEMENT and run the
(possibly mass-deactivating) action blind, which is the specific gap
`.scratch/roster-qa/issues/01` says it closed ("not discovered only after the
(irreversible) action already ran").

**Desired behavior:**
A failed preview fetch should not silently look identical to "nothing will
be deactivated." Either block IMPLEMENT until a preview successfully loads
(with a retry action), or show an explicit "Preview unavailable — proceed
with caution" banner distinct from the normal empty-preview state.

**Key interfaces:**
- Preview fetch effect — `artifacts/roster-dashboard/src/pages/RosterBuilder.tsx:1181-1194`
- Warning panel render — same file, `implPreview` truthy-gated block (~line 2133-2153)
- IMPLEMENT button disabled condition — same file (~line 2207-2216)

**Acceptance criteria:**
- [ ] A preview fetch failure is visibly distinct from "this pattern
      deactivates nobody"
- [ ] Operator has a clear path to retry the preview, or IMPLEMENT is blocked
      until a preview is available
- [ ] Happy-path (preview loads normally) behavior unchanged

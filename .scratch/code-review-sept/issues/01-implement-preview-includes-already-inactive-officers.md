## Agent Brief

**Category:** bug (correctness — misleading destructive-action warning)
**Summary:** `computeOfficerPlan()` selects `existingOfficers` from
`officersTable` with no `active` filter, so the new implement-preview
endpoint (and the real implement route, which shares the same function)
reports every officer who isn't in the pattern as "will be deactivated" —
including officers that are *already* inactive from a prior implement.

**Current behavior:**
`artifacts/api-server/src/routes/rosterPatterns.ts:285`:
```ts
const existingOfficers = await db.select({ id: officersTable.id, name: officersTable.name }).from(officersTable);
```
No `.where(eq(officersTable.active, true))`. Lines 310-313 then compute:
```ts
const keepIds = new Set(newOfficerRows.map((o) => o.id!));
const deactivateIds = existingOfficers.map((o) => o.id).filter((id) => !keepIds.has(id));
const deactivatedOfficers = existingOfficers
  .filter((o) => !keepIds.has(o.id))
  .map((o) => ({ id: o.id, name: o.name }));
```
`deactivateIds`/`deactivatedOfficers` are "every existing officer not in this
pattern," regardless of whether they're already `active = false`. After a
few pattern implements, `GET /api/roster-patterns/:id/implement-preview`
returns a list padded with officers who are already inactive (some possibly
retired long ago), and `RosterBuilder.tsx`'s Implement dialog renders that
verbatim:

> ⚠ This pattern will deactivate {implPreview.deactivatedOfficers.length}
> officer(s) not in it

— overstating the real impact, obscuring which currently-active officers are
actually affected, and can trigger the `keepCount === 0` copy ("every
currently active officer") when the true state is "every officer ever
created."

Because `implement` (the real, writing route) calls the same
`computeOfficerPlan()`, this isn't just a display bug: the real `deactivateIds`
passed to the `UPDATE officers SET active = false WHERE id IN (...)` also
includes already-inactive officers — harmless in effect (they're already
inactive) but confirms the plan computation itself, not just the preview
rendering, is wrong.

**Desired behavior:**
`existingOfficers` (and therefore `deactivateIds`/`deactivatedOfficers`) is
scoped to currently-active officers only, so the preview and the actual
deactivate step both report/act on officers this implement would newly
deactivate.

**Key interfaces:**
- `computeOfficerPlan()` — `artifacts/api-server/src/routes/rosterPatterns.ts:275-314`
- `GET /api/roster-patterns/:id/implement-preview` — same file, ~line 316
- `POST /api/roster-patterns/:id/implement` — same file, ~line 331 onward (shares `computeOfficerPlan`)
- Rendered warning — `artifacts/roster-dashboard/src/pages/RosterBuilder.tsx` (Implement dialog, `implPreview.deactivatedOfficers`)

**Acceptance criteria:**
- [ ] `computeOfficerPlan()` filters `existingOfficers` to `active = true`
      before computing `deactivateIds`/`deactivatedOfficers`
- [ ] `GET /api/roster-patterns/:id/implement-preview` on a pattern implemented
      more than once no longer lists already-inactive officers
- [ ] The `keepCount === 0` "every currently active officer" copy in
      `RosterBuilder.tsx` still fires correctly when it's actually true
